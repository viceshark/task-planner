# Task Planner

Планировщик задач команды: бесконечный календарь по дням, строки — сотрудники, в ячейках — задачи
с релизом и оценкой. Spring Boot + SQLite, вход по логину/паролю, поднимается одной командой в Docker.

## Возможности

- **Бесконечный календарь** — горизонтальная прокрутка, дни подгружаются в обе стороны; кнопка «Сегодня».
- **Сотрудники** — добавление, переименование, цвет, удаление; порядок в списке меняется drag-and-drop.
- **Задачи** — добавляются в ячейку «сотрудник × день», у задачи есть **релиз** и **оценка** (часы).
- **Drag-and-drop задач** между днями и сотрудниками — релиз и оценка переезжают вместе с задачей.
- **Пролонгация** — задачу с оценкой больше 8ч можно растянуть на несколько рабочих дней (выходные
  пропускаются); часы делятся поровну, карточка показывается в каждом дне с меткой `2/3`.
- **Овертайм** — у задачи есть поле «овертайм, ч»: часы сверх нормы, они входят в занятость дня и
  считаются в аналитике отдельно.
- **Простой, аренда, отпуск** — события сотрудника на период: простой (можно часть дня), аренда
  (сотрудника забрали в другую команду), отпуск. Создаются из ячейки («+» → тип) или кнопкой «+ Событие».
- **Занятость за день** — часы задач и событий сотрудника за день; подсветка: 8ч — зелёный, меньше — жёлтый, больше — красный.
- **Кликабельные ссылки** — Jira-ключи (`PROJ-123`) и URL в тексте задачи становятся ссылками
  (базовый адрес Jira задаётся в поле над календарём).
- **Аналитика** — KPI (часы, загрузка, овертайм, простой, отпуск/аренда), загрузка по дням с ёмкостью
  команды, таблица релизов с **датой готовности** (следующий рабочий день после последней задачи релиза),
  овертайм и отсутствия по сотрудникам, сводная таблица; пресеты периода (неделя/месяц/квартал/30 дней).
  Отпуск и аренда уменьшают ёмкость, простой — нет (он показывает недозагрузку).
- **Безопасность** — Spring Security, форма входа, кнопка выхода в верхнем меню, CSRF для API.
- **Две темы оформления** — RetroWave (liquid glass × неон) и 90s (окно классического десктопа:
  бежевые панели, чёрные рамки, пиксельный логотип). Переключатель есть на странице входа и в верхнем меню;
  выбор хранится в cookie, страницы сразу рендерятся в нужной теме.

## Запуск в Docker

В `docker-compose.yml` два сервиса: приложение (`planner`) и reverse-proxy **Caddy**, который
принимает 80/443 и проксирует запросы в приложение. Наружу открыт только Caddy.

```bash
cp .env.example .env   # логин, пароль, домен
docker compose up -d --build
```

- На сервере с доменом: `https://ваш-домен` (см. раздел [Caddy и HTTPS](#caddy-и-https)).
- Локально (без `DOMAIN` в `.env`): <http://localhost>.

Логин/пароль по умолчанию — `admin` / `admin`. Переменные окружения (`.env` подхватывается compose автоматически):

| Переменная            | По умолчанию        | Описание                                   |
|-----------------------|---------------------|--------------------------------------------|
| `APP_USERNAME`        | `admin`             | Логин для входа                            |
| `APP_PASSWORD`        | `admin`             | Пароль для входа                           |
| `APP_SEED_EMPLOYEES`  | `true`              | Создать демо-сотрудников при пустой базе   |
| `DOMAIN`              | `http://localhost`  | Адрес сайта для Caddy (домен → HTTPS)      |

Данные: SQLite в томе `planner-data`, сертификаты Caddy в томе `caddy-data` — оба переживают
`docker compose down` и пересборку образа. Обновление на сервере:

```bash
git pull && docker compose up -d --build
```

## Caddy и HTTPS

Схема:

```
браузер ──HTTPS :443──▶ Caddy ──HTTP :8080──▶ planner (Spring Boot)
        ──HTTP  :80 ──▶ Caddy ──▶ редирект на https://
```

Конфигурация — файл `Caddyfile` (монтируется в контейнер только для чтения):

```
{$DOMAIN} {
    encode gzip zstd
    reverse_proxy planner:8080
}
```

- **`DOMAIN=task-planeur.vc-inc.tech`** — Caddy включает автоматический HTTPS: получает сертификат
  Let's Encrypt по протоколу ACME (проверка http-01 через порт 80), хранит его в томе `caddy-data`
  и сам продлевает примерно за 30 дней до истечения (срок действия — 90 дней). Ничего настраивать
  вручную не нужно. HTTP автоматически редиректит на HTTPS, включены HTTP/2 и HTTP/3.
- **`DOMAIN=http://localhost`** (по умолчанию) — префикс `http://` отключает TLS, Caddy отдаёт
  приложение по обычному HTTP на порту 80. Удобно для локальной работы.
- `reverse_proxy` передаёт в приложение заголовки `X-Forwarded-For` / `X-Forwarded-Proto`;
  в `application.yml` включён `server.forward-headers-strategy: native`, поэтому редиректы и cookie
  корректны за прокси.

Что нужно для HTTPS на сервере:

1. A-запись домена (или поддомена) в DNS → IP сервера. Проверка: `dig +short ваш-домен`.
2. Открытые порты 80 и 443: `sudo ufw allow 80,443/tcp`. Порт 80 обязателен — по нему Let's Encrypt
   проверяет владение доменом.
3. `DOMAIN=ваш-домен` в `.env` и `docker compose up -d`.

Диагностика:

```bash
docker compose logs --tail 50 caddy     # получение сертификата, ошибки прокси
curl -sI https://ваш-домен/login | head -1   # ожидается HTTP/2 200
```

Опционально: чтобы Let's Encrypt присылал письма о проблемах с продлением, добавьте в начало
`Caddyfile` глобальный блок с email:

```
{
    email you@example.com
}
```

## Локальный запуск

Нужны JDK 17+ и Maven.

```bash
mvn spring-boot:run
```

База создастся в `./data/planner.db`. Логин/пароль — `admin` / `admin`
(переопределяются переменными `APP_USERNAME` / `APP_PASSWORD`).

Тесты:

```bash
mvn test
```

## REST API

Все эндпоинты требуют авторизованной сессии; для изменяющих запросов нужен CSRF-заголовок
(фронтенд берёт его из мета-тегов страницы).

| Метод  | Путь                              | Описание                                  |
|--------|-----------------------------------|-------------------------------------------|
| GET    | `/api/employees`                  | Список сотрудников в порядке отображения  |
| POST   | `/api/employees`                  | Создать `{name, color}`                   |
| PUT    | `/api/employees/{id}`             | Изменить                                  |
| DELETE | `/api/employees/{id}`             | Удалить вместе с задачами                 |
| PUT    | `/api/employees/order`            | Новый порядок `{ids: [...]}`              |
| GET    | `/api/tasks?from=&to=`            | Задачи за период                          |
| POST   | `/api/tasks`                      | Создать `{employeeId, day, title, release, estimate, days, overtime}` |
| PUT    | `/api/tasks/{id}`                 | Изменить `{title, release, estimate, days, overtime}` |
| PATCH  | `/api/tasks/{id}/move`            | Перенести `{employeeId, day}` (день начала) |
| DELETE | `/api/tasks/{id}`                 | Удалить                                   |
| GET    | `/api/absences?from=&to=`         | События (простой/аренда/отпуск), пересекающие период |
| POST   | `/api/absences`                   | Создать `{employeeId, type, startDay, endDay, hoursPerDay, note}`; `type`: `DOWNTIME`, `RENTAL`, `VACATION` |
| PUT    | `/api/absences/{id}`              | Изменить                                  |
| DELETE | `/api/absences/{id}`              | Удалить                                   |
| GET    | `/api/settings` / PUT             | Базовый URL Jira                          |
| GET    | `/api/analytics?from=&to=`        | Агрегаты для страницы аналитики           |

## Структура

```
src/main/java/ru/planner
├── config/    Security, свойства, инициализация каталога SQLite, демо-данные
├── domain/    JPA-сущности (Employee, Task, Absence, AppSetting)
├── repo/      Spring Data репозитории
├── service/   Бизнес-логика и аналитика
├── api/       REST-контроллеры и DTO
└── web/       Контроллер страниц (Thymeleaf)
src/main/resources
├── schema.sql          Схема SQLite (создаётся при старте, идемпотентно; новые колонки — SchemaMigrator)
├── templates/          login, calendar, analytics + общие фрагменты
└── static/             css/app.css (база + RetroWave), css/theme-90s.css, fonts/ (Silkscreen, Space Mono),
                        js/common.js, js/calendar.js, js/analytics.js
```
